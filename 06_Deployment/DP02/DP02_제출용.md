# DP02 제출용

**모델 배포 개론 Day 2 — FastAPI로 모델 추론 API 만들기 · 체크포인트 답안**

## 1절 체크포인트 (FastAPI 소개)

**1. FastAPI가 Flask보다 모델 배포에 적합한 이유 세 가지는 무엇입니까?**
첫째, Pydantic 기반의 자동 입력 검증을 제공하여 요청 데이터의 타입과 형식을 자동으로 확인하고 잘못된 입력을 걸러낸다. 둘째, ASGI 기반의 비동기(async) 처리를 지원하여 동시에 들어오는 다수의 추론 요청을 효율적으로 처리한다. 셋째, Swagger UI(`/docs`) 형태의 API 문서를 자동으로 생성하여 API의 테스트와 공유가 용이하다.

**2. Uvicorn의 역할은 무엇이며, 왜 FastAPI와 함께 사용합니까?**
Uvicorn은 네트워크에서 HTTP 요청을 받아 처리하는 ASGI 웹 서버이다. FastAPI는 요청 처리 방식을 정의한 애플리케이션일 뿐 스스로 요청을 수신하지 못하므로, 이를 구동해 요청을 전달하고 응답을 반환하는 서버가 필요하다. FastAPI가 ASGI 방식으로 동작하므로 동일 규격의 Uvicorn을 함께 사용한다.

**3. `@app.get("/health")`에서 `get`과 `"/health"`는 각각 무엇을 의미합니까?**
`get`은 HTTP 메서드 GET을 의미하여 해당 경로로 GET 요청이 오면 아래 함수를 실행하도록 지정하고, `"/health"`는 요청을 받을 URL 경로(엔드포인트)로 서버의 정상 동작 여부를 확인하는 용도로 사용된다.

**4. FastAPI에서 dict를 반환하면 어떤 일이 자동으로 일어납니까?**
반환한 딕셔너리가 자동으로 JSON으로 직렬화되고, 응답 헤더에 `Content-Type: application/json`이 설정되며 기본 상태 코드 200과 함께 반환된다. 따라서 `json.dumps()`를 직접 호출하거나 헤더를 지정할 필요가 없다.

## 2절 체크포인트 (Path / Query / Body)

**1. `/models/sentiment-v1`에서 `sentiment-v1`은 어떤 종류의 파라미터입니까?**
URL 경로의 일부로 전달되는 경로 파라미터(Path Parameter)이며, 특정 리소스를 지정할 때 사용한다.

**2. `/models?status=running&limit=5`에서 `status`와 `limit`은 어떤 종류의 파라미터입니까?**
`?` 뒤에 `key=value` 형태로 전달되는 쿼리 파라미터(Query Parameter)이며, 주로 필터링·정렬·개수 제한 등 선택적 조건을 전달할 때 사용한다.

**3. 모델 추론 요청에 Request Body를 사용하는 이유는 무엇입니까?**
추론 입력은 이미지 픽셀 배열이나 긴 문장처럼 크고 구조화된 데이터라 URL에 담기 어렵기 때문에, 요청 본문(Body)에 JSON으로 담아 전송한다.

**4. FastAPI에서 함수의 파라미터가 Path, Query, Body 중 어디서 오는지 어떻게 판별합니까?**
FastAPI는 파라미터의 선언 방식과 타입으로 판별한다. 경로에 `{name}`으로 선언된 이름과 일치하면 Path, 경로에 없는 단순 타입이면 Query, Pydantic `BaseModel` 타입이면 Request Body로 인식한다.

## 3절 체크포인트 (Swagger UI)

**1. FastAPI에서 Swagger UI에 접속하려면 어떤 URL로 이동합니까?**
서버 주소 뒤에 `/docs`를 붙여 접속한다 (예: `http://127.0.0.1:8000/docs`).

**2. Swagger UI가 코드와 항상 동기화될 수 있는 이유는 무엇입니까?**
FastAPI가 실제 코드(경로·타입 힌트·Pydantic 모델)로부터 OpenAPI 스키마를 자동 생성하고 Swagger UI가 이를 렌더링하기 때문이며, 코드가 곧 문서의 원천이므로 항상 최신 상태로 유지된다.

**3. Pydantic 모델의 `Field(description=, examples=)`는 Swagger UI의 어디에 반영됩니까?**
`description`은 해당 필드의 설명으로, `examples`는 요청 본문의 예시 값(Example Value)으로 표시된다.

**4. Swagger UI와 ReDoc의 핵심 차이는 무엇입니까?**
Swagger UI(`/docs`)는 요청을 직접 실행해 볼 수 있는 대화형 문서이고, ReDoc(`/redoc`)은 실행 기능 없이 읽기 편하게 정리된 문서 뷰이다.

## 4절 체크포인트 (Pydantic 입력 검증)

**1. `text: str`과 `text: str = "기본값"`의 차이는 무엇입니까?**
`text: str`은 값이 반드시 있어야 하는 필수 필드이고, `text: str = "기본값"`은 값이 없으면 기본값을 사용하는 선택 필드이다.

**2. `Field(..., min_length=1, max_length=5000)`에서 `...`은 무엇을 의미합니까?**
`...`(Ellipsis)은 해당 필드가 필수 항목임을 의미하며, 기본값 없이 반드시 값을 제공해야 한다.

**3. 422 에러 응답에서 `loc` 필드는 어떤 정보를 담고 있습니까?**
검증이 실패한 위치(location)를 담으며, 예를 들어 `["body", "text"]`처럼 어느 부분의 어떤 필드에서 오류가 났는지를 알려준다.

**4. `response_model`을 지정하면 어떤 이점이 있습니까?**
응답 데이터가 지정한 스키마에 맞게 검증·필터링되어 정의된 필드만 반환되고, 응답 구조가 문서에 자동 표시되며 반환 타입이 보장되어 API 일관성이 높아진다.

## 마치며 — Day 2 종합 점검

**1. 모델을 서버 시작 시 한 번만 로드해야 하는 이유는 무엇입니까?**
모델 로드는 무겁고 느린 작업이므로 매 요청마다 로드하면 응답이 느려지고 자원이 낭비된다. 서버 시작 시 한 번만 로드해 메모리에 두고 재사용하면 추론을 빠르고 효율적으로 처리할 수 있다.

**2. pixel_values가 784개가 아닌 요청이 들어오면 어떤 일이 발생합니까? 이를 처리하는 코드를 직접 작성했습니까?**
입력 크기가 28×28=784개가 아니면 검증에 실패하여 422(입력 검증 실패) 오류가 반환된다. 이를 위해 픽셀 개수를 확인하여 784개가 아니면 오류를 반환하도록 검증 코드를 작성하였다.

**3. HTTPException(status_code=503)은 어떤 상황에서 사용했습니까? 왜 500이 아니라 503입니까?**
모델이 아직 로드되지 않는 등 서버가 일시적으로 요청을 처리할 수 없을 때 사용하였다. 503(Service Unavailable)은 "지금은 불가하나 곧 가능한" 일시적 상태를, 500은 예기치 못한 내부 오류를 의미하므로, 원인을 더 정확히 나타내는 503을 사용한다.

**4. Swagger UI에서 PredictRequest의 description과 examples가 어디에 표시됩니까?**
해당 예측 엔드포인트의 Request Body 영역에 표시되며, `description`은 각 필드 설명으로, `examples`는 요청 본문의 예시 값(Example Value)으로 나타난다.
